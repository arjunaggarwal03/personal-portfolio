I've been helping turn Lightfield's product operations into a public API and
Python SDK. Both are used by our own agent, so the same object has to make sense
in the product, the SDK, and an action a person may need to review.

I keep returning to five questions:

- What can be created or edited?
- Who owns the action?
- Which state is durable?
- What can be retried?
- What can a person inspect or reverse?

A public API cannot rely on knowledge that lives in the team. Names, states,
examples, and error behavior all become part of the product once someone else
builds against them.

Documentation has been a useful test. If an operation is hard to name or show
in an example, the boundary underneath it is probably still unclear.
